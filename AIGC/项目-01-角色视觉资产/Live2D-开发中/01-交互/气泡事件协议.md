# AI 自主决定的轻吐槽气泡协议 v0.2

## 设计原则

- AI 结合语境自行决定是否生成 aside；**不合适时返回 null**。
- aside 是角色扮演文本，不是模型内部推理链。
- 前端不按固定百分比掷骰子，不从预设吐槽列表随机抽签。
- 工程仅限制：用户开关、敏感场景禁用、长度、安全过滤、避免连续刷屏。

## 结构化模型输出

~~~json
{
  "reply": "这次已经整理好了。",
  "aside": {
    "text": "差点以为还有第八版……",
    "expression": "tease_smile"
  }
}
~~~

没有必要时：

~~~json
{
  "reply": "资料已经整理好了。",
  "aside": null
}
~~~

reply 为正式答复，不受气泡影响。aside.text 建议不超过 20 字，expression 可为 neutral / tease_smile / tease_brow / tease_sideeye 等。后端应通过 Schema 及安全检查，不通过则将 aside 置 null，不影响 reply。

## 模型提示规范

“以正常、有用的回答为主；只有当对话确实适合小小的俏皮反差时，才额外生成一句简短、轻巧的吐槽作为 aside；其他情况 aside 为 null。严肃或隐私主题绝不生成。aside 不等于内部推理。”

## 处理链路

1. Agent 生成 reply 和自主判断的可选 aside。
2. 后端进行验证、尊重用户开关、检查语境及防刷屏；必要时清除 aside。
3. 前端正常渲染 reply/TTS；有合法 aside 时额外显示约 2–3 秒。
4. Live2D Adapter 可把 expression 映射到 Cubism 表情，不覆盖 TTS 口型。
5. UI 使用 textContent，不能插入不可信 HTML。

## 验收重点

- 多数普通话题不显示气泡；表达不模板化。
- 用户关闭、严肃/隐私话题不显示。
- 不暴露私聊信息、API 密钥、内部推理链。
- 一次最多一个，不排队；连续刷屏可被产品层节制。
